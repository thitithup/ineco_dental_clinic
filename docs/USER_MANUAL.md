## 1. การเข้าสู่ระบบ (Login)

ทุกครั้งที่เริ่มใช้งาน ให้เจ้าหน้าที่หรือคุณหมอล็อกอินผ่านหน้าจอหรือ API:

- **Endpoint:** `POST /api/v1/auth/login`
- **ข้อมูลที่ต้องกรอก:** `username` และ `password`

### ตัวอย่างบัญชีเริ่มต้นในระบบ:
| บทบาท | Username | Password | เหมาะสำหรับ |
|---|---|---|---|
| **เจ้าหน้าที่ต้อนรับ** | `receptionist` | `DentalPass123!` | จัดการคนไข้, จองคิว, นัดหมาย |
| **ทันตแพทย์จัดฟัน** | `dr_somchai` | `DentalPass123!` | ตรวจคนไข้จัดฟัน, บันทึกการรักษา |
| **ทันตแพทย์รักษารากฟัน** | `dr_kanya` | `DentalPass123!` | รักษารากฟัน, บันทึกการรักษา |

> **คำแนะนำด้านความปลอดภัย:** เมื่อได้รับ Token ให้ส่งใน Header `Authorization: Bearer <token>` ทุกครั้ง

## 2. คู่มือสำหรับเจ้าหน้าที่เคาน์เตอร์ (Receptionist Guide)

### 2.1 การค้นหาคนไข้ด่วนด้วยเบอร์โทรหรือชื่อ
เมื่อคนไข้เดินมาที่เคาน์เตอร์ ให้ขอเบอร์โทรศัพท์หรือชื่อ-นามสกุล เพื่อค้นหาประวัติได้ทันที:

- **Endpoint:** `GET /api/v1/patients?query=0812345678` หรือ `?query=สมชาย`
- **ผลลัพธ์:** ระบบจะแสดงประวัติคนไข้ทันที พร้อมเลข HN, โรคประจำตัว และประวัติแพ้ยา

### 2.2 การลงทะเบียนคนไข้ใหม่พร้อมบันทึกประวัติแพ้ยา
หากเป็นคนไข้ใหม่ที่ยังไม่เคยมีประวัติในระบบ:
- **Endpoint:** `POST /api/v1/patients`
- **ข้อมูลสำคัญที่ต้องกรอก:**
  - `first_name`: ชื่อจริง (เช่น สมศรี)
  - `last_name`: นามสกุล (เช่น ใจสะอาด)
  - `phone_number`: เบอร์โทรศัพท์ 10 หลัก (ห้ามซ้ำ)
  - `date_of_birth`: วันเดือนปีเกิด รูปแบบ `YYYY-MM-DD` (เช่น `1995-04-12`)
  - `medical_conditions`: โรคประจำตัว เช่น โรคเบาหวาน, โรคหัวใจ, ความดันโลหิตสูง
  - `drug_allergies`: **ประวัติการแพ้ยา (สำคัญมาก!)** เช่น แพ้ยาเพนนิซิลิน (Penicillin), แพ้ยาซัลฟา (Sulfa)

> **ข้อสังเกต:** หากเบอร์โทรศัพท์ซ้ำกับคนไข้ที่มีอยู่แล้ว ระบบจะแจ้งเตือน `409 CONFLICT` เพื่อป้องกันการสร้างประวัติคนไข้ซ้ำซ้อน

### 2.3 การดูรายชื่อแพทย์และความเชี่ยวชาญ
ก่อนทำการนัดหมาย สามารถตรวจสอบได้ว่าแพทย์ท่านใดเข้าเวรและเชี่ยวชาญด้านใด:
- **Endpoint:** `GET /api/v1/dentists`
- **ระบบจะแสดง:**
  - ทพ. สมชาย ใจดี (ความเชี่ยวชาญ: ทันตกรรมจัดฟัน - Orthodontics)
  - ทพญ. กัญญา รักษาฟัน (ความเชี่ยวชาญ: วิทยารักษารากฟัน - Endodontics)

### 2.4 การนัดหมายคิวรักษาและจัดการคิวซ้อนทับ
- **Endpoint:** `POST /api/v1/appointments`
- **ข้อมูลที่ใช้ในการจอง:**
  ```json
  {
    "patient_id": 1,
    "dentist_id": 2,
    "appointment_time": "2026-10-15T10:00:00",
    "duration_minutes": 30,
    "treatment_type": "ขูดหินปูน (Scaling)",
    "notes": "คนไข้สะดวกช่วงเช้า"
  }
  ```
- **ระบบ Anti-Collision ป้องกันคิวซ้อน (ครอบคลุมทั้งหมอและคนไข้):**
  - **กรณีหมอติดคิว:** หากจองคิวคุณหมอท่านเดิมในช่วงเวลาที่ติดนัดหมายอื่นอยู่ ระบบจะปฏิเสธการจองทันที (`409 CONFLICT`)
  - **กรณีคนไข้ติดคิว:** หากคนไข้ท่านเดิมมีนัดกับหมอท่านอื่นในช่วงเวลาเดียวกันอยู่แล้ว ระบบจะปฏิเสธทันที ป้องกันไม่ให้คนไข้มี 2 นัดหมายซ้อนกัน
  - **เวลาทำการของคลินิก:** นัดหมายต้องอยู่ในช่วง **09:00 - 20:00 น.** เท่านั้น และไม่สามารถจองเวลาย้อนหลังในอดีตได้
  - **วิธีแก้ปัญหา:** ให้เสนอเวลาถัดไปให้คนไข้ (เช่น 10:30 น.) หรือเลือกคุณหมอท่านอื่นที่ว่างอยู่ในเวลานั้น

### 2.5 การยกเลิกหรือเลื่อนคิวนัดหมาย
หากคนไข้โทรมาขอยกเลิกหรือเลื่อนนัด:
- **Endpoint:** `PATCH /api/v1/appointments/{appointment_id}/status`
- **ระบุสถานะใหม่:** `{"status": "CANCELLED"}`
- คิวที่ถูกยกเลิกจะถูกปลดล็อกทันที ทำให้สามารถรับนัดคนไข้อื่นในช่วงเวลานั้นได้

### 2.6 การดึงข้อความแจ้งเตือนคนไข้ล่วงหน้า 1 วัน (SMS / LINE Reminders)
ทุกๆ เย็นหรือช่วงบ่าย เจ้าหน้าที่เคาน์เตอร์สามารถดึงรายการคนไข้ที่มีนัดวันพรุ่งนี้ เพื่อส่งข้อความเตือนนัดหมายทาง SMS หรือ LINE:
- **Endpoint:** `GET /api/v1/reminders/upcoming` (ระบบจะดึงคิววันพรุ่งนี้ให้อัตโนมัติ)
- **หรือระบุวันที่เจาะจง:** `GET /api/v1/reminders/upcoming?date=2026-10-15&reminder_status=PENDING`
- **ตัวอย่างข้อความที่ระบบสร้างให้ทันที (พร้อม Copy ส่งคนไข้):**
  > *"เรียนคุณ สมศักดิ์ รักฟัน คลินิกทันตกรรม Ineco Dental ขอแจ้งเตือนนัดหมาย ขูดหินปูน (Scaling) กับ ทพ. สมชาย ใจดี ในวันที่ 15/10/2026 เวลา 10:00 น. หากต้องการเลื่อนนัดกรุณาโทร 02-123-4567"*
- **การอัปเดตสถานะหลังส่งข้อความ:**
  - เมื่อกดส่งข้อความแล้ว ให้เปลี่ยนสถานะเป็น `SENT`:
    - **Endpoint:** `PATCH /api/v1/appointments/{appointment_id}/reminder-status`
    - **Payload:** `{"reminder_status": "SENT"}`
  - เมื่อคนไข้ตอบกลับมายืนยันเวลา ให้เปลี่ยนสถานะเป็น `CONFIRMED`:
    - **Payload:** `{"reminder_status": "CONFIRMED"}`
  - ช่วยให้เจ้าหน้าที่ในทีมเห็นตรงกันว่าคนไข้ท่านใดยังไม่ได้ติดต่อ และท่านใดยืนยันคิวแล้ว

## 3. คู่มือสำหรับคุณหมอฟัน (Dentist Guide)

### 3.1 การตรวจสอบตารางนัดหมายของตนเอง
เมื่อคุณหมอล็อกอินเข้าระบบ คุณหมอสามารถดูตารางนัดหมายของตนเองประจำวันได้ทันที:
- **Endpoint:** `GET /api/v1/appointments?date=2026-10-15`
- ระบบจะกรองเฉพาะคิวคนไข้ของคุณหมอโดยอัตโนมัติ โดยเรียงลำดับตามเวลาจากเช้าไปบ่าย

### 3.2 การตรวจประวัติสุขภาพและคำเตือนแพ้ยาของคนไข้
ก่อนเริ่มทำหัตถการ ให้ตรวจสอบประวัติสุขภาพของคนไข้:
- **Endpoint:** `GET /api/v1/patients/{patient_id}`
- **จุดที่ต้องให้ความสำคัญ:**
  - ฟิลด์ `drug_allergies`: ระบุประวัติการแพ้ยาชา ยาแก้อักเสบ หรือยาปฏิชีวนะ
  - ฟิลด์ `medical_conditions`: ระบุโรคประจำตัวที่มีผลต่อการทำฟัน เช่น โรคหัวใจ หรือการรับประทานยาละลายลิ่มเลือด

### 3.3 การบันทึกประวัติการรักษา (ระบุซี่ฟันและ Doctor Notes)
เมื่อทำหัตถการเสร็จสิ้น คุณหมอสามารถบันทึกประวัติการรักษาลงในเวชระเบียน:
- **Endpoint:** `POST /api/v1/treatments`
- **สิทธิ์การใช้งาน:** เฉพาะบัญชี `DENTIST` เท่านั้น (เจ้าหน้าที่เคาน์เตอร์ไม่สามารถแก้ไขหรือบันทึกข้อมูลส่วนนี้ได้)
- **ตัวอย่างข้อมูล:**
  ```json
  {
    "appointment_id": 1,
    "patient_id": 1,
    "tooth_number": "18",
    "treatment_details": "ผ่าฟันคุดกรามบนขวา กรอตัดฟันและเย็บ 2 เข็ม",
    "doctor_notes": "นัดตัดไหมในอีก 7 วัน แนะนำคนไข้ประคบเย็น 24 ชม. แรก"
  }
  ```
- **ระบบทำงานอัตโนมัติ:** เมื่อคุณหมอบันทึกประวัติการรักษาพร้อมระบุ `appointment_id` สถานะของนัดหมายดังกล่าวจะเปลี่ยนเป็น `COMPLETED` ให้ทันทีโดยไม่ต้องไปกดเปลี่ยนสถานะเอง

### 3.4 การดูประวัติการรักษาย้อนหลังของคนไข้
คุณหมอสามารถเรียกดูประวัติการรักษาครั้งก่อนๆ ของคนไข้ได้ทั้งหมด:
- **Endpoint:** `GET /api/v1/treatments/patient/{patient_id}`
- แสดงรายการหัตถการที่เคยทำ ซี่ฟันที่เคยรักษา และบันทึกติดตามผลของคุณหมอแต่ละท่าน

## 4. คำถามที่พบบ่อยและการแก้ไขปัญหา (FAQs)

**Q1: เจ้าหน้าที่เคาน์เตอร์สามารถบันทึกประวัติการรักษาแทนคุณหมอได้หรือไม่?**  
**ตอบ:** ไม่ได้ เพื่อความถูกต้องตามมาตรฐานวิชาชีพและกฎหมายเวชระเบียน ระบบจะปฏิเสธคำขอด้วยรหัส `403 FORBIDDEN` หากผู้ส่งข้อมูลไม่ใช่บทบาท `DENTIST`

**Q2: หากคนไข้ต้องการนัดขูดหินปูนและอุดฟันพร้อมกัน ควรทำอย่างไร?**  
**ตอบ:** เจ้าหน้าที่สามารถเพิ่มระยะเวลา `duration_minutes` ในการนัดหมาย เช่น จาก 30 นาที เป็น 60 นาที ระบบ Anti-Collision จะล็อกเวลาให้คุณหมอครบทั้ง 60 นาที ป้องกันไม่ให้มีนัดหมายอื่นมาแทรก

**Q3: กรณีคนไข้เปลี่ยนเบอร์โทรศัพท์ เจ้าหน้าที่แก้ไขอย่างไร?**  
**ตอบ:** ให้เรียกใช้ `PUT /api/v1/patients/{id}` โดยระบุเบอร์โทรศัพท์ใหม่ ระบบจะตรวจสอบว่าเบอร์ใหม่ไม่ซ้ำกับคนไข้อื่น และอัปเดตข้อมูลให้ทันที
